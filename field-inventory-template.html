F2 · Task and Data Plan: ASU Student Club Application

The form contains 10 purposeful controls, including a radio group and checkboxes. This is a fictional front-end prototype; it does not transmit or store information.

Field inventory — one row per planned control
Visible label / question Why necessary now? Required? Native control/type Submitted name/value Autocomplete/inputmode Constraint/instruction Sensitivity and minimization decision
Name (required) Lets the club officers address the attendee and match the request. Yes input type=text name = attendee-entered fictional name autocomplete=name 2–80 characters; no rigid name pattern. Personal data. Use fictional names in tests; no legal name is needed for this prototype.
Email address (required) Provides a reply route for the registration request. Yes input type=email email = attendee-entered fictional email autocomplete=email Browser email syntax; max 254 characters; example john@test.com Contact information. Do not use a real address or send data.
Preferred contact method (required) Lets the club officers know how a real follow-up should be made. Yesselectcontact_method = email or phone N/A Must choose Email or Phone; blank prompt is not valid. Communication preference; no phone number is collected.
Club of interest (required) Identifies which club the applicant wants to join. Yes select club = game-development / design / photography / outdoor-adventure N/A Choose one listed club. Low sensitivity; choices are limited to the purpose of the form.
Preferred session (required) Helps club officers understand which meeting format/time may work. Yes radio group session = weekday-evening / saturday-morning / online N/A One radio choice is required. Scheduling preference; no additional schedule details requested.
Number of attendees (required) Helps the club estimate participation for planning. Yes input type=number attendees = integer 1–4 inputmode=numeric Required; minimum 1, maximum 4, step 1; includes the submitter. Low sensitivity; cap limits unnecessary group details.
Accessibility or participation support Allows the club to follow up about participation support without asking for a diagnosis. No input type=checkbox support_requested = yes when checked N/A Optional checkbox; unchecked value is not submitted. Potentially sensitive if elaborated. Ask only whether follow-up is wanted.

Anything else the club officers should know? Allows brief practical context not covered by choices. Notextarea notes = attendee-entered text N/A Optional; max 500 characters; instruction says no sensitive details. Free text can reveal sensitive data; optional, limited, and discouraged for private details.
Future club event updates Separates optional future-news interest from this request. No input type=checkbox updates = yes when checked N/A Optional checkbox; unchecked value is not submitted. Contact preference. Do not use it as consent to unrelated messages.
