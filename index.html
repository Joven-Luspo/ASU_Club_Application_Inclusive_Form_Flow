ASU Student Club Application

Use this prototype to apply to join a student club at Arizona State University. It is designed for students who want to attend a on campus club and takes about 3 minutes to complete.

F1 · Purpose and Expectations

Complete this form to tell the club officers which club you would like to join and how to contact you about the request.

  • Time: About 3 minutes.
  • Required fields: Marked “(required)”. All other fields are optional.
  • After submission: In a real service, the club officers would review the request and email next steps.
  • Privacy: Do not enter real personal information. Use fictional details for testing. No information is collected by this prototype.

* Required fields are marked “(required)”.

F4 · Requirements and Validation

Complete all fields marked required. Choose a club and preferred meeting time, use an email address such as john@test.com, and enter an expected attendance count from 1 through 4. The browser checks required fields, email format, and the numeric range before allowing a submission attempt.

F5 · State and Recovery Specimen

Default

Fields begin empty, except the attendee count defaults to 1. Help text appears before entry.

Focus

Keyboard focus has a high-contrast gold outline. Use Tab and Shift+Tab to move between controls.

Required

Required fields say “(required)” and use the native required attribute. The browser identifies missing values on submission.

Valid

Example format is shown; the field is read-only to keep this specimen separate from the form.

Invalid

Error: Enter an email address in the format name@example.com. Keep your other entries and correct this field.

Disabled

Disabled controls are visibly muted and cannot be edited.

Static server-returned error example

We could not process this fictional request. The email address needs attention. Review the field labeled “Email address · invalid specimen,” enter a complete address such as john@test.com, and try again. Your other entries should remain in place.

F2 · Task and Data Plan

The completed field inventory explains each control, why it is needed, whether it is required, its submitted name/value, autocomplete or input mode, constraints, and data-minimization decision.

F6 · System and Evidence

Design system

This page extends a compact design system with CSS custom properties for color, spacing, radius, and readable line length; a responsive paired-field layout; visible keyboard focus; error styling with text and color. At narrow widths, paired fields stack into one column.
